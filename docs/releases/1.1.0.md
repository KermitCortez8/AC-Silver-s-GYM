# MVP 1.1.0: horarios, asistencia y membresías

## Objetivo y alcance

Entregar una versión identificable de los tres módulos implementados en
`develop`, partiendo del commit `e6f4498`. La versión es 1.1.0 porque el
repositorio ya contiene el tag v1.0.0.

| Módulo | Flujo incluido | Pantallas |
| --- | --- | --- |
| Horarios | Gestionar horarios por servicio y realizar matrículas; validar cupos y cruces de horario | `/admin/service-schedules`, `/admin/enrollment`, `/user/schedule` |
| Asistencia | Registrar entrada y salida como administrador, consultar historial, corregir y anular registros; consultar asistencia propia como cliente | `/admin/attendance`, `/user/attendance` |
| Membresías | Gestionar planes, registrar cliente con membresía y consultar sus membresías | `/admin/plans`, `/admin/clients`, `/registro` |

Autenticación, clientes, servicios y configuración de Supabase son dependencias
del MVP. Los demás módulos existentes permanecen disponibles, pero no forman
parte de la aceptación de esta entrega.

## Preparación

1. Seguir el README para configurar frontend y backend sin versionar secretos.
2. Usar una instancia de prueba de Supabase con el esquema base del gimnasio.
   Las migraciones de este repositorio son incrementales, no crean toda la base.
3. Revisar y aplicar en orden `backend/migrations/001` a `006` (archivos SQL).
   Para recordatorios automáticos, configurar además las funciones en `supabase`
   y la migración `007`, siguiendo sus instrucciones internas.
4. Preparar cuentas de administrador y cliente, servicios, un plan y horarios
   de prueba. Si se verifica el pago, usar Stripe en modo de prueba.
5. Iniciar los servicios según el README.

## Aceptación manual pendiente en Supabase de prueba

- [ ] Crear y editar un plan; registrar un cliente y comprobar su membresía y vigencia.
- [ ] Crear un horario por servicio y comprobar que aparece en el calendario.
- [ ] Matricular al cliente con membresía válida; comprobar rechazo de cupo lleno,
      duplicados y cruces; cancelar la matrícula y comprobar la liberación del cupo.
- [ ] Como administrador, registrar entrada y salida; comprobar historial,
      corrección y anulación con su auditoría.
- [ ] Como cliente, consultar su semana e historial y comprobar que no puede
      registrar ni modificar asistencias de otros clientes.
- [ ] Recargar las pantallas y comprobar persistencia de los cambios.

Esta lista requiere datos y servicios externos; las pruebas automatizadas no
sustituyen su ejecución. No se aplican migraciones ni se procesan pagos reales
como parte de la preparación de Git.

## Validación automatizada

```bash
cd frontend
npm ci
npm test
npm run build
cd ../backend
python -m pip install -r requirements.txt pytest flake8
AUTH_SECRET_KEY=ci-only-test-key-not-for-production-0123456789abcdef python -m pytest -q
flake8 . --count --select=E9,F63,F7,F82 --show-source --statistics
```

El CI también construye las imágenes Docker y valida Compose. Se ejecuta para
`main`, `develop`, `release/**`, `hotfix/**` y tags `v*`.

## Git Flow

- `main`: versiones cerradas.
- `develop`: integración del desarrollo.
- `feature/<nombre>`: funcionalidades que parten de `develop` y regresan a ella.
- `release/1.1.0`: estabilización y documentación de este MVP desde `develop`.
- `hotfix/<version>`: correcciones urgentes desde `main`, integradas también en `develop`.
- `v1.1.0`: tag anotado sobre el merge de la release en `main`.

Cierre local de esta entrega, después del commit y las comprobaciones:

```bash
git switch main
git merge --no-ff release/1.1.0 -m "release: MVP 1.1.0 de horarios, asistencia y membresias"
git tag -a v1.1.0 -m "MVP 1.1.0: horarios, asistencia y membresias"
git switch develop
git merge --no-ff main -m "chore: integrar release 1.1.0 en develop"
```

Se conserva la rama release para facilitar la revisión. La publicación remota
se realiza por separado, respetando las protecciones y revisiones del repositorio:

```bash
git push --atomic origin main develop release/1.1.0 refs/tags/v1.1.0
```

El tag identifica el código; no representa un despliegue ni una certificación
de las pruebas manuales pendientes.
